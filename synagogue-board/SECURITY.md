# אבטחת מידע – מאור

## מה מוגן בקוד
- **כללי Firestore** (`firestore.rules`): קריאה/כתיבה לפי תפקיד (סופר-אדמין / גבאי / סגן גבאי / מסך). גבאי **לא** יכול לשנות חבילה, השעיה או מנוי. הרשמה עצמית מוגבלת לשדות מוגדרים ובסטטוס "ממתין". מסכי TV (חיבור אנונימי) יכולים רק לקרוא תכנים להצגה ולדווח "דופק" למסכים מוגדרים.
- **כותרות אבטחה** (`next.config.js`): CSP, HSTS, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy; דפי ניהול/התחברות מסומנים noindex ו-no-store.
- **התחברות**: סיסמה חזקה בהרשמה (8+ תווים, אות ומספר), ניתוק אוטומטי מלוח הניהול אחרי 30 דקות ללא פעילות, "שכחתי סיסמה" עם הגבלת קצב, honeypot ותשובה זהה בין אם החשבון קיים או לא.
- **XSS**: אין `dangerouslySetInnerHTML`; דוחות PDF עוברים ניקוי (סקריפטים, onX, javascript:) והטקסטים מוּבְרָחִים.
- **API**: `/api/halacha` עם רשימת מקורות סגורה, הגבלת קצב ושגיאות כלליות (לא חושפות פרטים פנימיים).
- **גיבוי**: ייצוא/שחזור מוגבל לאוספי תוכן מותרים בלבד.

## מה צריך לעשות ידנית (פעם אחת)
1. **לפרסם את הכללים**: Firebase Console › Firestore › Rules › להדביק את `firestore.rules` › Publish.
2. **להגביל את מפתח ה-API** (Google Cloud Console › Credentials): HTTP referrers = כתובת האתר שלכם בלבד.
3. **Firebase Authentication**: להפעיל Email enumeration protection; לבחור מדיניות סיסמה (min 8); אם אפשר – אימות דו-שלבי לחשבון הסופר-אדמין.
4. **App Check** (reCAPTCHA Enterprise / v3) ל-Firestore ול-Auth – חוסם שימוש במפתח מחוץ לאפליקציה.
5. **תקציב והתראות** ב-Google Cloud (Billing › Budgets) – הגנה מפני שימוש לרעה בחיבורים אנונימיים.
6. **משתני סביבה ב-Vercel בלבד** (לא ב-git): `FIREBASE_SERVICE_ACCOUNT`, `SMTP_*`/`RESEND_API_KEY`, `FORGOT_PASSWORD_NOTIFY_TO`. אם אחד מהם נחשף – לסובב מיד.
7. **גיבוי תקופתי**: ייצוא Firestore מתוזמן, או הורדת קובץ הגיבוי מ"הגדרות מערכת" אחת לשבוע.
8. סופר-אדמין אחד לפחות עם אימייל שרק אתם שולטים בו; לאשר גבאים חדשים רק אחרי אימות טלפוני.

## נקודות לדעת
- כתובת מסך (`/display?s=<id>`) ציבורית בכוונה: כל מי שמכיר את ה-id יכול לראות את תכני התצוגה (לא נתוני גבייה/חברים).
- נתוני גבייה, חברים וקבלות נקראים רק על ידי חברי בית הכנסת המאושרים.
- מפתח ה-Firebase Web (`NEXT_PUBLIC_FIREBASE_*`) ציבורי מטבעו ואינו סוד; ההגנה האמיתית היא כללי Firestore + הגבלת המפתח ל-referrers + App Check. אסור שמפתח Service Account או סיסמאות ייכנסו ל-git או לקוד לקוח.
- מסך TV מחובר אנונימית ויכול לקרוא כל בית כנסת שה-id שלו ידוע (לא ניתן להגביל זאת בכללים); לכן ה-id הוא מזהה אקראי של Firestore ואין לשים בתכני התצוגה מידע רגיש. אוספי גבייה/חברים/קבלות/תקלות/מלאי/הוצאות/`private` חסומים לקריאה למסכים.
- משתמש אנונימי אינו יכול ליצור פרופיל `users/*`; כל נתיב שלא מוגדר בכללים (כולל אוספים עתידיים) חסום כברירת מחדל. אוסף חדש בקוד חייב להתווסף גם ל-`isContentCol`/`isPrivateCol` בכללים ול-`lib/types.js`.
- נתיבי `/api/admin/*` ו-`/api/auth/onboard` דורשים ID token תקף (ו-super_admin במקרה של איפוס סיסמה); `/api/auth/forgot-password` ו-`/api/halacha` ציבוריים עם הגבלת קצב. הגנת `/admin` ו-`/super-admin` בצד לקוח (הפניה ל-/login) – האבטחה האמיתית היא כללי Firestore.
- קישור קבוצת וואטסאפ נפתח רק אם הוא `https://`; קישור תרומה (`payUrl`) מוצג כ-QR בלבד.
